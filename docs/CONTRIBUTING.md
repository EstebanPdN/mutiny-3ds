# Contributing to Mutiny 3DS

Start with the [architecture](ARCHITECTURE.md), the [source map](SOURCE-MAP.md) and the
[development guide](DEVELOPMENT.md).

## Development loop

1. Install the tools listed in the development guide and generate the game data from your own
   `Mutiny.swf`.
2. Make the change. Gameplay code follows the original ActionScript classes: keep names and
   behavior comparable with the source in `build/extract/scripts/`.
3. Check it on the macOS build with a scripted test, then build for 3DS with
   `tools/build_3ds.sh`.
4. In the pull request, say what you tested and where: macOS, Azahar or a real console.

## Guidelines

* Keep the bottom-screen layout fixed: team health and minimap always visible, with only the
  context panel changing.
* New interface art is pixel art generated by script in the original palette (`tools/gen_ui.py`),
  with integer scaling only.
* Label port-specific gameplay changes in the code and in the [changelog](../CHANGELOG.md).
* Keep public text in English.

## What not to commit

Never commit `Mutiny.swf`, extracted or converted game data (`build/`, `data/`, `assets/`,
`src/game/lines.h`), saves, dumps, local SDK installations or credentials. `.gitignore` covers
these paths.

## Reporting bugs

Use the issue templates. Include the version, the console model or emulator, and the exact
steps. A screenshot or a short video helps a lot.
